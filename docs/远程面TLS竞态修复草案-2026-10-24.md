## TL;DR

`remote_conn_guard.tls_gate_protocol_class` 的「accept 后先装 gate、再异步 `start_tls`」模式,在 **uvloop** 下存在本质竞态:与 accept 同批到达的 ClientHello 会被投递给 gate 的 `data_received`(先 `pause_reading()` 也拦不住),密文进 `_pending` 并在 `_hand_over` 时回放给 HTTP 层——TLS 层永远收不到 hello,握手饿死,10 秒后 abort。「连上即写」的客户端(node fetch/undici,含 Node 24 后量子 ~1583B 大 hello,跨段更易同批)高概率命中;curl(Schannel,connect 与 hello 分拍)实测恒通;stdlib 事件循环下同代码实测无恙。**生产 daemon 经 uvicorn `get_loop_factory()` 跑在 uvloop 上,故中招。**

修复建议(方案 A,已实证):TLS 移回原生路径(uvicorn `ssl_certfile` / `create_server(ssl=)`——SSL 协议层在 accept 时即安装,无投递窗口),guard 保留 HTTP 层职责(header deadline / 连接上限 / flood 上限)。最小复现三口对照:**gate 式 0–1/6,原生 ssl 6/6**。

## 根因(最小复现实证)

复现脚本见附录(双 variant + 原生对照三口,uvloop 跑)。关键日志:

```
[pause] EARLY 1583B in phase=init
[pause] handshake FAILED: ConnectionAbortedError: SSL handshake is taking longer than 10 seconds: aborting the connection
```

- `phase=init` = `connection_made` 已返回、握手 task 尚未运行——**ClientHello(1583B,Node 24 默认后量子组)此时已投递给 gate 的 `data_received`**,`pause_reading()` 未能阻止(uvloop 的传输层实现与 stdlib `_SelectorSocketTransport` 的暂停时序不同);
- 去掉 `pause_reading` 的对照 variant 同样中招(0–1/6)——竞态是「gate 在 task 调度间隙内收到数据」本身,**pause 只是无效补丁**;
- stdlib loop 下同代码 6/6 → 竞态为 uvloop 特有投递时序;
- 生产 daemon:`unified_daemon` 末尾 `asyncio_run(serve_pair(...), loop_factory=main_config.get_loop_factory())` → uvicorn `loop="auto"` → **uvloop 在装即用**;
- hello 密文进 `_pending` 后,`_hand_over` 把它回放给 HTTP 协议(`for chunk in self._pending: http.data_received(chunk)`)——喂错了层,TLS 握手从启动就注定饿死;
- 已排除假说:后量子大 hello 本身(OPENSSL_CONF 限定经典组复测无改善,纯时序问题)、MTU(DF 1472 通)、路径(TCP raw 通、curl 恒通)、代理(无 env、TUN 无)。

## 修复方案

### 方案 A(推荐,已实证):TLS 回原生路径,guard 退守 HTTP 层

`remote_listener.make_servers` 改造:

1. `uvicorn.Config` 增 `ssl_certfile=str(remote.cert), ssl_keyfile=str(remote.key)`(uvicorn 原生 TLS——SSL 协议层在 accept 时即装,无投递窗口;**9443 对照口 6/6 实证**);
2. `http=` 从 `tls_gate_protocol_class(...)` 换成 `guarded_protocol_class(base, limits)`——header deadline(`HEADER_DEADLINE_S`)、`MAX_WAITING/MAX_OPEN_CONNECTIONS`、`MAX_PENDING_BYTES` 的 HTTP 层守卫全部保留;
3. `QuietServer.shutdown()` 里对 `gate_class.slm_limits.handshaking` 的逐个 shutdown 移除(不再有 gate);`tls_gate_protocol_class` 与 `server_tls_context` 保留导出但生产不再走(`server_tls_context` 仍被 `_tls_context` 用于证书校验);
4. daemon 重启(§6.1 序列:停 watchdog timer+service → 停 hermes-gateway → restart superlocalmemory → 起回)。

**代价(如实)**:
- pre-TLS 连接计数(握手中的连接也占 cap)失效——慢握手洪水不再被 10s 掐掉,而是等 asyncio 默认 60s 握手超时;cap 只护到 HTTP 层。缓解可后补:socket backlog 已是 uvicorn 默认;如需,后续在 `create_server(..., ssl_handshake_timeout=10)` 层面自管(需绕过 uvicorn 的 server 创建,工程量另议);
- `TLS_HANDSHAKE_TIMEOUT_S` 定制(10s)退化为 uvloop 默认 60s。

### 方案 B(否决):保留 gate,把窗口内密文喂回 TLS 层

asyncio 的 `start_tls` 无公开注入面;私有路径(`SSLProtocol._ssl_io_adaptor` 等)不稳定。且「无 pause variant 同样中招」证明该模式在 uvloop 上不可救,**否决**。

### 方案 C(否决):客户端 pacing 中继

工作机本地加 pacing TCP 中继规避时序。丑、扩攻击面、每个 node 客户端都要带,**否决**(仅作过桥应急,未部署)。

## 附录:最小复现脚本(probe2.py,2026-10-24 判定结果)

跑法:`python3 probe2.py uvloop`(去参数跑 stdlib loop);客户端用 node fetch 连发 6 次/口。
2026-10-24 判定矩阵(uvloop,node 24 工作机实连):

| 口 | 形态 | 结果 |
|---|---|---|
| 9441 | gate 式,无 pause | 0/6 |
| 9442 | gate 式,pause_reading(TLSGate 同款) | 0–1/6 |
| 9443 | 原生 `create_server(ssl=)` | **6/6** |

```python
# probe2.py — TLS gate 竞态最小探针:pause_reading+start_tls(TLSGate 式)vs 直连,uvloop/stdlib 双跑
# 相位:init(任务未跑)/hs(握手进行)/ready;hs 期收到字节=密文早到=竞态实锤。
import asyncio, pathlib, ssl, sys

BASE = pathlib.Path.home() / '.superlocalmemory/remote/tls'
CTX = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
CTX.minimum_version = ssl.TLSVersion.TLSv1_2
CTX.load_cert_chain(str(BASE / 'server.pem'), str(BASE / 'server.key'))
RESP = b'HTTP/1.1 200 OK\r\nContent-Length: 2\r\nConnection: close\r\n\r\nok'

def make(pause: bool):
    class P(asyncio.Protocol):
        phase = 'init'
        def connection_made(self, t):
            self.t = t; self.phase = 'init'
            if pause:
                t.pause_reading()
            asyncio.get_running_loop().create_task(self.hs())
        async def hs(self):
            self.phase = 'hs'
            try:
                self.tls = await asyncio.get_running_loop().start_tls(
                    self.t, self, CTX, server_side=True, ssl_handshake_timeout=10)
            except Exception as e:
                print(f'[{"pause" if pause else "nopause"}] handshake FAILED: {type(e).__name__}: {str(e)[:80]}', flush=True)
                return
            self.phase = 'ready'
        def data_received(self, data):
            if self.phase != 'ready':
                print(f'[{"pause" if pause else "nopause"}] EARLY {len(data)}B in phase={self.phase}', flush=True)
                return
            self.tls.write(RESP)
        def eof_received(self): return None
    return P

class Native(asyncio.Protocol):
    """原生 ssl= 路径:protocol 在 accept 时即被 SSLProtocol 包裹,收到即解密数据。"""
    def connection_made(self, transport):
        self.transport = transport
    def data_received(self, data):
        self.transport.write(RESP)
    def eof_received(self): return None

async def main():
    loop = asyncio.get_running_loop()
    s1 = await loop.create_server(make(False), '0.0.0.0', 9441)
    s2 = await loop.create_server(make(True), '0.0.0.0', 9442)
    s3 = await loop.create_server(Native, '0.0.0.0', 9443, ssl=CTX)
    print('probe2 up: 9441 no-pause / 9442 pause / 9443 native-ssl', flush=True)
    async with s1, s2, s3:
        await asyncio.Event().wait()

if __name__ == '__main__':
    if len(sys.argv) > 1 and sys.argv[1] == 'uvloop':
        import uvloop
        asyncio.run(main(), loop_factory=uvloop.EventLoopPolicy().new_event_loop)
    else:
        asyncio.run(main())
```
