# SLM 改进建议 — 基于 10 种主流 Agent Memory 方案基准对比

> 来源：[当前10种主流LLM Agent Memory方案对比](https://arxiv.org/abs/2504.19413)
> 日期：2026-05-09
> 状态：备忘录，非当前 Sprint

---

## 一、行业基准核心发现

### 统一框架四组件

| 组件 | 行业最佳实践 |
|------|-------------|
| **信息提取** | 直接归档 + 摘要式 + 图式三种范式并存 |
| **记忆管理** | 关联 / 整合 / 三层迁移 / 更新 / 遗忘过滤 |
| **记忆存储** | 向量存储为主流，树状层级（MemTree）综合最优 |
| **信息检索** | 向量检索最主流，图遍历增强，LLM 辅助查询重构 |

### 关键性能结论

1. **信息完整性是基础**：保留原始消息 > 纯图三元组提取（Mem0 > Mem0^g）
2. **关联能力决定多跳推理上限**：缺乏关联操作的方法在多会话任务中极差
3. **时间推理重依赖模型能力**：现有方法普遍缺专门时空处理组件
4. **性能与成本正相关**：MemTree/MemOS 准确率最高但 token 开销也最高

## 二、SLM 现有优势（超越全部10种方案）

| 能力 | 对比 |
|------|------|
| **多 Agent 视角隔离** | 独有——现有方案全为单 Agent 假设 |
| **三层记忆域（personal/share/global）** | 独有——MemoryOS 三层是「时间尺度」，SLM 是「社会尺度」 |
| **信息完整性** | ✅ 保留原文，匹配行业最佳 |
| **关联能力** | ✅ Entity Graph + Entity Merge |
| **领域标签** | ✅ Skill-Domain Tags + ScopeWeights |
| **数学基础** | ✅ Fisher-Rao / Sheaf / Langevin（行业中少数有数学层的方案） |
| **本地优先** | ✅ SQLite + 向量嵌入，全本地运行 |

## 三、改进建议（优先级排序）

### P1：树状记忆聚合（借鉴 MemTree）

**问题**：当前 SLM 记忆为扁平列表 + Entity Graph。长对话场景下，检索「上次文化祭发生了什么」难以高效定位相关场景集群。

**方案**：引入**三层树状聚合**
- **叶子**：原文消息（当前已有）
- **场景节点**：对话片段自动聚类为场景（如「废弃医院探索」「拉面店夜话」）
- **章节节点**：场景节点聚合为叙事单元

**预期收益**：
- 支持多粒度查询（「关于文化祭的一切」vs「032号场景的具体对话」）
- 自顶向下检索效率提升
- 为 Knot Loom 的叙事引擎功能做前置准备

**与现有架构关系**：基于 Entity Graph 构建，场景节点→实体关联链路已有

---

### P2：三层记忆生命周期（借鉴 MemoryOS）

**问题**：当前 SLM 不区分短期/长期记忆，所有记忆使用相同存储策略，长对话场景下检索速度线性下降。

**方案**：引入**STM→MTM→LPM 生命周期**
- **STM**（短期记忆）：当前会话，固定长度 FIFO
- **MTM**（中期记忆）：活跃话题缓存，按语义+关键词聚合
- **LPM**（长期档案）：稳定用户/Agent 画像，跨会话持久

**迁移策略**：
- STM→MTM：FIFO 驱动，队列满时聚合
- MTM→LPM：热度评分（访问次数 + 时间衰减），阈值触达则晋升
- 低热度淘汰：MTM 中未访问的记忆优先驱逐

**预期收益**：长期运行不降速，记忆管理成本可控

**与现有架构关系**：三层记忆域（personal/share/global）已存在，新增生命周期维度

---

### P3：记忆关联链接 + 遗忘曲线（借鉴 A-MEM + MemoryBank）

**问题**：当前 Entity Graph 只关联实体，不显式关联记忆条目之间的因果关系。遗忘纯靠检索排序，无主动淘汰机制。

**方案 A：记忆关联链接（A-MEM 的 Zettelkasten 思想）**
- 新记忆入库时，LLM 判断与哪些历史记忆存在因果/时序关联
- 建立显式记忆链路（「废弃医院探索 → 下水道出口 → 拉面店」）
- 检索命中一条时联动拉取关联链

**方案 B：艾宾浩斯遗忘衰减（MemoryBank）**
- 每条记忆记录重要性权重 + 末次访问时间
- 低重要性 + 长未访问 = 衰减，可在检索时降权或静默淘汰

**预期收益**：多跳推理 ↑，存储成本 ↓

## 四、与 Knot Loom 的关系

| 改进 | SLM（公开） | Knot Loom（私有叙事引擎） |
|------|-----------|------------------------|
| **P1 树状聚合** | 通用场景聚类 | 场景→章节聚合是叙事引擎核心 |
| **P2 生命周期** | 通用 STM/MTM/LPM | 结合叙事时间线，MTM=当前剧情弧 |
| **P3 关联链接** | 通用记忆关联 | 因果链=叙事引擎的事件推理 |
| **P3 遗忘曲线** | 通用淘汰策略 | 配合规则引擎（感知边界过滤） |

> 核心原则：**SLM 做通用层 → Knot Loom 做叙事专精层 → 改进从 SLM 进入，叙事特化留在 Knot Loom**
